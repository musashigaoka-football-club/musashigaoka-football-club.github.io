# 表の定義（SCHEMA）

このファイルは、このフォルダの CSV を読み書きする人と AI のための**契約書**である。列を足す・意味を変えるときは、先にここを直す。

- 決定の経緯：[[soccer-dataset-layer]]（2026-09-30 採用）
- 読み書きするスクリプト：`~/dev/tokyo-soccer-brackets`（Vault の外）。環境変数 `SOCCER_DATASET_DIR` でこのフォルダを受け取る

## 共通の決まり

| 項目 | 決まり | 理由 |
|---|---|---|
| 形式 | CSV・UTF-8（BOM なし）・改行 LF・1行目は列名 | git で差分が見え、どの道具でも読める。BOM は他言語の道具を静かに壊す（[[windows-encoding-pitfalls]]） |
| 列名 | 英語の snake_case | SQL（DuckDB）で引用符が要らない。日本語の意味はこのファイルに書く |
| 値 | 日本語でよい（校名・大会名・回戦など） | 原文に近いほうが人も AI も照合しやすい |
| 1セル | 1つの値だけ | 詰め込むと集計のたびに分解が要り、AI が誤る |
| 空欄 | 「分からない」を表す。0 や「なし」と区別する | 0-0 と「スコア不明」を取り違えないため |
| 保存しないもの | 強さの点数・順位・勝つ見込み・番狂わせ・集計値 | 計算で出る値を保存すると、元データを直すたびに古くなる |
| 行の並び | 各表の主キーの昇順 | 書き出すたびに並びが変わると、差分が読めなくなる |

## ID の決め方

ID は**内容から決まるもの**と**一度振ったら変えないもの**の2種類がある。

| ID | 例 | 決め方 |
|---|---|---|
| `school_id` | `S0123` | 一度振ったら変えない。新しい学校は最後の番号の次。欠番は再利用しない |
| `team_id` | `S0123-A` | `school_id`＋区分（A/B/C…）。区分の書かれていないトップチームは `A` |
| `comp_id` | `2026-選手権-1次予選`・`2025-Tリーグ-T5` | `年度-大会-段階`。内容から決まる |
| `match_id` | 下記 | 内容から決まる。**同じ試合には、何度読み直しても同じ ID が付く** |
| `source_id` | `R0042` | 一度振ったら変えない |

`match_id` の形：

- トーナメント：`{comp_id}|{area}/{block}|{round}|{team_id の小さいほう}|{大きいほう}`
  - 同じ大会の同じ表・同じ回戦で、同じ2チームが当たるのは1度だけなので、これで1試合が決まる
- リーグ戦：`{comp_id}|{area}/{block}|{home_team_id}>{away_team_id}|{n}`
  - `n` は同じ組み合わせ（ホームとアウェイの向きも同じ）の何試合目か（1から）。日付順、日付が無ければ出典の並び順

**同じ `match_id` が2行あれば、それは二重計上である。** 検査はこれを止める（2026-09 に、同じトーナメント表の別版を両方読んで334試合を2度数えていた）。

## 表

### schools.csv — 学校（とクラブ）1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `school_id` | 文字 | 主キー |
| `name` | 文字 | 表示に使う短い名前（例：`武蔵丘`）。都立・私立の別は付けない |
| `official_name` | 文字 | 正式名（例：`東京都立武蔵丘高等学校`）。分からなければ空欄 |
| `roster_name` | 文字 | 東京都高体連サッカー専門部の加盟校一覧に載っている名前（例：`駒澤大学`）。加盟校一覧に無ければ空欄。**加盟校は、試合の記録が1つも無くてもこの表に載せる**（地区ごとの加盟校数を数えるため） |
| `kind` | 文字 | `都立` / `私立` / `国立` / `区立` / `高専` / `クラブ` / `合同チーム` / `読み取り不能` / `不明`。`合同チーム`・`読み取り不能` は `school_overrides.csv` で人が決める |
| `district` | 整数 | 東京都高体連サッカー専門部の地区（1〜8）。分からなければ空欄 |
| `city` | 文字 | 所在の区市町村 |
| `legacy_key` | 文字 | 移行前に校名を寄せて作っていたキー（`build_outputs.normalize` の結果）。移行の突き合わせ用 |
| `note` | 文字 | 別の学校と取り違えやすい、改称した、などの注意 |
| `merged_into` | 文字 | 名寄せで別の学校にまとめた行は、まとめ先の `school_id`。それ以外は空欄 |

- 名前の似た別の学校は、必ず別の行にする（例：`昭和第一`（文京区）と `昭和第一学園`（立川市）、私立の `武蔵` と都立の `武蔵`）
- 改称は同じ学校なので1行のまま。旧校名は `school_names.csv` に持つ。**統合（2校が1校になった）は改称ではない**ので、別々の行のまま `note` に書く
- **名寄せでまとめた行は消さずに残し、`merged_into` を書く。** 消すと `school_id` が再利用されるおそれがあり、古い記録やコミットに残った ID の行き先も分からなくなる。`merged_into` のある行を、ほかの表から参照してはいけない（検査で止める）

### school_merges.csv — 名寄せの判断1件につき1行

| 列 | 型 | 意味 |
|---|---|---|
| `variant_key` | 文字 | まとめられる側の `legacy_key`（主キー） |
| `canonical_key` | 文字 | まとめ先の `legacy_key` |
| `squad` | 文字 | 校名に区分の文字が残っていた場合の区分（`B`・`C`）。空欄なら元の区分のまま |
| `kind` | 文字 | `表記`（読み取りの誤り・表記ゆれ・略し方）/ `区分`（校名に区分の文字が残った）/ `改称` |
| `note` | 文字 | 判断の根拠 |

- **人が確かめた判断だけを書く。** 機械が拾った候補は `_staging/school-merges.md` で目視してから、ここに移す（2026-10-02 の初回は85件を確認）
- 書き出し（`dataset/export.py`）はこの表を読んで、試合・チーム・順位表の参照をまとめ先に付け替え、まとめられた側の `schools.csv` の行に `merged_into` を書く。**この表が名寄せの正本で、`merged_into` はその結果である**
- `kind=改称` の書き方は `school_names.csv` に `旧校名` として残す

### school_overrides.csv — 人が決めた区分1件につき1行

| 列 | 型 | 意味 |
|---|---|---|
| `legacy_key` | 文字 | 区分を決める学校の `legacy_key`（主キー）。名寄せでまとめた学校は指さない（まとめ先を指す） |
| `kind` | 文字 | `合同チーム`（2校以上が組んだチーム）/ `読み取り不能`（PDF の文字が化けて校名が読めない） |
| `note` | 文字 | 判断の根拠（合同チームなら加わった学校） |

- 区分は加盟校一覧にも名前の形にも出てこないため、名寄せと同じく人の判断を入力の表に持つ。書き出しはこの表を読んで `schools.csv` の `kind`・`note` を上書きする（2026-10-13）
- この2つの区分の学校は、**学校一覧と順位の母数から外す。試合と点数の計算には残す**（合同チームと戦った相手の点数は、その試合で動いているため）
- 候補は `scripts/propose_name_rules.py`（Vault の外）が規則で拾い、`_staging/school-merges.md` で目視してからここに移す

### school_names.csv — 校名の書き方1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `name` | 文字 | 出典に現れた書き方そのまま（例：`都・武蔵丘`・`都立武蔵丘高等学校A`・`武蔵丘高`） |
| `school_id` | 文字 | 指す学校 |
| `kind` | 文字 | `表記` / `略称` / `旧校名` |
| `first_season` / `last_season` | 整数 | その書き方が出てくる最初と最後の年度 |

- 主キーは `name`。**同じ書き方が2つの学校を指すことはない**。指しうる場合（`都・武蔵` と `武蔵`）は、原文の書き方を区別して登録する
- 取り込みのとき、出典の校名はこの表で `school_id` に変える。**この表に無い書き方が出たら取り込みを止め、人に確かめる**（黙って新しい学校を作ると、寄せ漏れが別の学校として数えられる）

### teams.csv — チーム1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `team_id` | 文字 | 主キー（`S0123-A`） |
| `school_id` | 文字 | 学校 |
| `squad` | 文字 | `A` / `B` / `C` … |
| `first_season` / `last_season` | 整数 | 記録に出てくる範囲 |

大会（総体・選手権・新人戦・関東）に出るのは各校の `A` だけ。リーグ戦には `B` 以下も出る。

### competitions.csv — 大会の段階・リーグの部1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `comp_id` | 文字 | 主キー |
| `season` | 整数 | 年度（4月始まり。3月の試合は前の年度） |
| `series` | 文字 | 大会：`総体` / `選手権` / `新人戦` / `関東`。リーグ：`Tリーグ` / `プリンス関東` / `NSリーグ` など |
| `stage` | 文字 | 下の表の値。リーグは部（`T5`・`1部`・`2部A`） |
| `edition` | 文字 | 回次（`第105回`）。無ければ空欄 |
| `level` | 文字 | `1次`（支部・地区の予選）/ `都大会` / `リーグ` |
| `format` | 文字 | `トーナメント` / `リーグ` |
| `district` | 整数 | 地区リーグのときの地区。それ以外は空欄 |

大会の段階（`stage`）と水準（`level`）：

| series | stage | level | 注意 |
|---|---|---|---|
| 総体 | 支部予選 | 1次 | |
| 総体 | 都1次トーナメント | 都大会 | 原文は「一次トーナメント」。**名前に「一次」とあるが都大会である**（2026-09 に1次と取り違え、2015・2021年度の都大会進出を落とした） |
| 総体 | 都2次トーナメント | 都大会 | |
| 選手権 | 1次予選 | 1次 | |
| 選手権 | 2次予選 | 都大会 | |
| 新人戦 | 地区大会 | 1次 | |
| 新人戦 | 都大会 | 都大会 | |
| 関東 | 東京都予選 | 都大会 | |

リーグの格（プリンス関東 → T1〜T5 → 地区リーグ）は `series` と `stage` から分かるので、別の列にしない。

### matches.csv — 試合1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `match_id` | 文字 | 主キー（上記） |
| `comp_id` | 文字 | 大会の段階・リーグの部 |
| `area` | 文字 | 支部・地区（例：`南支部（第5・6地区）`・`第5地区`）。無ければ空欄 |
| `block` | 文字 | 表の中のブロック（例：`南6`・`【10】`）。リーグはブロック・組。無ければ空欄 |
| `page` | 整数 | 出典が PDF のとき、試合が載っているページ（1から）。同じ PDF の別ページの表を区別する |
| `round` | 文字 | `1回戦`〜`4回戦` / `ブロック決勝` / `準々決勝` / `準決勝` / `決勝` / `3位決定戦`。リーグ戦は節（`第3節`）、分からなければ空欄 |
| `match_no` | 文字 | 表に書かれた試合番号（`【31】` など） |
| `date` | 日付 | `YYYY-MM-DD`。1日に決まらないときは空欄 |
| `date_text` | 文字 | 出典の日付の書き方そのまま（`11/17、23、24` など） |
| `team_a` / `team_b` | 文字 | `team_id`。リーグ戦では `team_a` がホーム |
| `raw_a` / `raw_b` | 文字 | 出典の校名の書き方そのまま |
| `score_a` / `score_b` | 整数 | 90分（延長を含む）の得点 |
| `pk_a` / `pk_b` | 整数 | PK戦の得点。PK戦が無ければ空欄 |
| `extra_time` | 0/1 | 延長戦があったか |
| `halves` | 文字 | 前後半の内訳（出典にあれば。例：`1-0 / 1-1`） |
| `status` | 文字 | 下の表 |
| `winner` | 文字 | 勝ったチームの `team_id`。引き分け・不明は空欄 |
| `winner_basis` | 文字 | 勝者の根拠：`赤線`（トーナメント表の勝ち上がり線）/ `スコア` / `外部` / `訂正` / `リーグ` |
| `source_id` | 文字 | 主に使った出典 |
| `note` | 文字 | |

`status` の値：

| 値 | 意味 | 移行前の「状態」 |
|---|---|---|
| `済` | 結果（スコアと勝者）が分かる | 終了・スコアのみ記載（赤線未反映）・赤線が両側（スコアで判定） |
| `勝者のみ` | 勝者は分かるがスコアが無い | スコア記載なし |
| `不戦` | 不戦勝・棄権 | 不戦勝・棄権 |
| `結果不明` | 行われたかどうかも含めて結果が記録に無い | 未実施・勝者不明 |
| `予定` | これから行われる（リーグ戦の日程） | リーグの「実施」が済でない行 |

**`結果不明` を「行われなかった」と読んではいけない。** 古い年度はアーカイブに結果の入る前の版しか残っていないことが多く、試合は行われている。

### standings.csv — 順位表の1行

| 列 | 型 | 意味 |
|---|---|---|
| `comp_id` / `block` / `team_id` | 文字 | 主キー（3つの組） |
| `raw_team` | 文字 | 出典での表記（例：`都立紅葉川高校`・`修徳高校Ｃ`） |
| `rank` | 整数 | 順位 |
| `played` / `won` / `drawn` / `lost` | 整数 | 試合・勝・分・敗 |
| `goals_for` / `goals_against` / `points` | 整数 | 得点・失点・勝点 |
| `basis` | 文字 | `公式`（主催者の順位表）/ `試合から計算` |
| `as_of` | 日付 | いつ時点の順位表か |
| `source_id` | 文字 | |

公式の順位表と、`matches.csv` から計算した成績は一致しないことがある（主催者の更新が遅れる。例：2026-09-27 の試合が9-30時点で未反映）。**どちらかを黙って上書きしない。**

### sources.csv — 出典1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `source_id` | 文字 | 主キー |
| `kind` | 文字 | `トーナメント表PDF` / `Webページ` / `掲示板` / `観戦記事` / `本人の報告` |
| `feed` | 文字 | 取得の経路：`高体連PDF` / `高校サッカードットコム` / `goalnote` / `星取表` / `Tリーグ公式` / `Tリーグ過去` / `プリンス` / `本人の報告`。集計でどの経路の試合を使うかを選ぶときに使う |
| `url` | 文字 | 元の URL |
| `archive_url` | 文字 | インターネットアーカイブの URL（あれば） |
| `title` | 文字 | PDF の題・ページの題 |
| `sha256` | 文字 | 取得したファイルのハッシュ（PDF のみ）。同じ中身かどうかを確かめるため |
| `note` | 文字 | |

### match_sources.csv — 試合と出典の対応1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `match_id` / `source_id` / `seq` | 文字・整数 | 主キー（3つの組）。`seq` は同じ出典に同じ試合が2度載っているときの番号（ふつうは1） |
| `role` | 文字 | `主`（`matches.source_id` と同じ）/ `重複`（同じ試合を載せた別の出典。同じ表の別版など）/ `補完`（結果を埋めるのに使った出典） |
| `raw_a` / `raw_b` | 文字 | その出典での校名の書き方 |
| `flipped` | 0/1 | その出典では `team_a` と `team_b` が逆に書かれているか（リーグ戦のホームとアウェイ） |
| `date_text` / `round` | 文字 | その出典での日付・回戦（リーグ戦は節） |
| `src_row` | 整数 | その出典のファイルの中で何行目にあったか（1から）。同じ日の試合の並び順を出典どおりに再現するために持つ（点数の計算は試合の順番で結果が変わる）。大会の試合は、トーナメント表の読み取り結果を並べた順（PDF の頁・ブロック・回戦の順）での位置 |
| `src_seq` | 整数 | リーグ戦の重なりを整理したとき（日付のある行を先に、出典ごとに）の並びでの位置（1から）。年度・リーグ・日付が同じ試合の順番を再現するために持つ。大会の試合は空欄 |

1つの試合が複数の出典に載っていることは多い。重なりを**捨てずにここへ残す**ことで、「なぜこの試合は1行なのか」を後から確かめられる。出典ごとの書き方（校名・日付・節）もここに残すので、出典の形をそのまま読んでいた旧来の集計（例：点数の計算は goalnote・Tリーグ公式・プリンスの3経路だけを読む）を、この表から同じ結果で再現できる。

### corrections.csv — 人が確かめて直した値1つにつき1行

| 列 | 型 | 意味 |
|---|---|---|
| `match_id` | 文字 | 直した試合 |
| `field` | 文字 | 直した列（`matches.csv` の列名） |
| `value` | 文字 | 正しい値 |
| `reason` | 文字 | 何を見て直したか |
| `source_id` | 文字 | 根拠の出典（あれば） |
| `date` | 日付 | 直した日 |

取り込み（PDF の読み直しなど）のたびに、最後にこの表を当て直す。`match_id` が内容から決まるので、読み直しても訂正が外れない。

## 検査（外のスクリプトが行う）

どれか1つでも引っかかれば、書き出しもコミットも止める。

1. 各表の主キーが重複していない
2. 参照先が実在する（`team_id` → `teams`、`school_id` → `schools`、`comp_id` → `competitions`、`source_id` → `sources`）
3. `status` が `済` の行はスコアがあり、`winner` がスコア（またはPK）と矛盾しない
4. トーナメントの1つの表で、試合数 ＝ 出場チーム数 − 1 を超えない
5. 同じ大会・同じ回戦に、同じチームが2度出ていない
6. `school_names.csv` に無い校名の書き方が、取り込みの途中に現れていない
7. `merged_into` のある学校を、ほかの表（`teams`・`matches`・`standings`・`school_names`）が参照していない。`school_merges.csv` の `variant_key`・`canonical_key` が `schools.csv` に実在し、まとめ先がさらに別の学校にまとめられていない

8. `school_overrides.csv` の行が実在の学校（名寄せでまとめていないもの）を指し、`schools.csv` の `kind` に当たっている
